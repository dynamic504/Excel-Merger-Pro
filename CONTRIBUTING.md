## 💬 How to Contribute

### **🐛 Found a Bug?**
1. Check [existing issues](https://github.com/dynamic504/Excel-Merger-Pro/issues) to avoid duplicates
2. Click [New Issue](https://github.com/dynamic504/Excel-Merger-Pro/issues/new) → Choose **Bug Report**
3. Fill out the template with as much detail as possible
4. Attach screenshots or sample files if possible

### **💡 Have a Feature Idea?**
1. Check [existing issues](https://github.com/dynamic504/Excel-Merger-Pro/issues?q=is%3Aissue+label%3Aenhancement)
2. Click [New Issue](https://github.com/dynamic504/Excel-Merger-Pro/issues/new) → Choose **Feature Request**
3. Describe your use case clearly
4. Explain how it would improve the app

### **📚 Improve Documentation?**
1. Fork the repository
2. Edit README.md or other docs
3. Submit a pull request with your changes

### **💻 Contribute Code?**
1. Check [open issues](https://github.com/dynamic504/Excel-Merger-Pro/issues) with `help-wanted` label
2. Comment on the issue to express interest
3. Follow the [Development Setup](#development-setup) guide
4. Create a feature branch and make your changes
5. Submit a pull request

## 🐛 Reporting Bugs

**Good bug reports** help us fix issues faster. Please include:

✅ **DO:**
- Be specific and detailed
- Include system information (Windows version, Excel version)
- Provide steps to reproduce
- Attach sample files (without sensitive data)
- Include error messages or screenshots

❌ **DON'T:**
- Report bugs in comments on closed issues
- Share confidential or sensitive data
- Use vague descriptions like "it doesn't work"
- Assume we know what you're talking about

### Bug Report Template

When you create a bug report, use our [bug report template](.github/ISSUE_TEMPLATE/bug_report.md).

## 💡 Suggesting Features

**Good feature suggestions** are:

## 🛠️ Development Setup

### **Prerequisites**
- Windows 7 or later
- Microsoft Excel 2010 or later
- A text editor (VS Code, Notepad++, etc.)
- Git

### **Getting Started**

1. **Fork the repository**
   ```bash
   Click "Fork" on the GitHub page
   ```

2. **Clone your fork**
   ```bash
   git clone https://github.com/YOUR_USERNAME/Excel-Merger-Pro.git
   cd Excel-Merger-Pro
   ```

3. **Create a feature branch**
   ```bash
   git checkout -b feature/your-feature-name
   ```

4. **Make your changes**
   - Edit the `.hta` file (it's HTML/VBScript)
   - Test thoroughly on your machine

5. **Commit your changes**
   ```bash
   git add .
   git commit -m "✨ Add your feature description"
   ```

6. **Push to your fork**
   ```bash
   git push origin feature/your-feature-name
   ```

7. **Create a Pull Request**
   - Go to the original repository
   - Click "New Pull Request"
   - Select your branch and describe your changes

## 📝 Making Changes

### **Code Style**

- Keep code clean and well-commented
- Use descriptive variable names
- Follow existing code patterns
- Test on multiple Windows versions if possible
- Test with different Excel versions if possible

### **Commit Messages**

Use clear, descriptive commit messages:

```
✨ Add feature description       # New feature
🐛 Fix bug description           # Bug fix
📖 Update documentation          # Docs
♻️  Refactor code section        # Refactoring
⚡ Improve performance           # Performance improvement
🔐 Fix security issue            # Security
```

### **Testing**

Before submitting a pull request:

- ✅ Test the app on Windows 10/11
- ✅ Test with different Excel versions
- ✅ Test with different file formats (.xlsx, .xls, .csv)
- ✅ Test with large files (1000+ rows)
- ✅ Test with small files (10-20 rows)
- ✅ Verify no sensitive data leaks

## 📤 Submitting Changes

### **Pull Request Process**

1. **Update README.md** if your changes affect usage
2. **Fill out the PR template** completely
3. **Keep commits clean** - squash if needed
4. **Be ready to discuss** your changes
5. **Respond to feedback** promptly

### **PR Title Format**

Use clear titles that explain what you did:

```
✨ Add command-line interface support
🐛 Fix freezing with large files
📖 Improve Quick Start guide
⚡ Optimize memory usage
🔐 Add input validation
```

### **PR Description Template**

When you submit a PR, include:

```markdown
## Description
Brief description of what this PR does.

## Related Issue
Fixes #123 (if applicable)

## Type of Change
- [ ] Bug fix
- [ ] New feature
- [ ] Breaking change
- [ ] Documentation update

## Testing
Describe how you tested this change.

## Screenshots
If applicable, add screenshots showing the change.

## Checklist
- [ ] I've tested this thoroughly
- [ ] I've updated documentation
- [ ] I've followed the code style
```
